Federated Missing-Person Search — Build Plan

The scoped-down version. One federated module, five small components, four parallel lanes, and exactly one novelty claim that carries the report.

Duration 12 weeks Team 4 Hardware Laptops only New datasets to request None Companion Design report

Everything in this plan runs on a laptop, uses only datasets you can download today, and involves no hardware purchase, no access request, and no protocol you cannot read in an afternoon.

The novelty, in one sentence

Paste this into your abstract

Existing federated face-recognition work federates the recognition model itself, which is impractical at edge scale. We freeze a public face recognition backbone entirely and federate only a 0.4 M-parameter domain adapter that learns each site's camera degradation profile — cutting per-round communication by roughly two orders of magnitude while recovering low-resolution matching accuracy that no single node could reach alone, with cancelable watchlist templates and differentially private update aggregation on top.

That claim is small, true, measurable in three weeks, and absent from all sixteen papers in your survey. It is enough. Two supporting contributions come almost free and give you extra report sections:

  • Cancelable watchlist templates — the missing person's face is distributed as a keyed binary code, never as an image. About 30 lines of code, directly extends paper [2].
  • Track-level decisions instead of frame-level — requires k of n frames in one track to agree before raising an alert. Closes the exact gap paper [1] left open, and it makes the demo video look far better.

Resist adding a fourth

Every extra mechanism costs a week you do not have and adds nothing to the grade. If someone suggests blockchain, homomorphic encryption, or a second biometric modality, the answer is "future work" and it goes in the last paragraph of the report.

What you are actually building

Five components · none of them large

ComponentRoughlyWhat it is
Degradation pipeline~80 linesOpenCV chain: downsample → motion blur → noise → JPEG. Turns clean LFW/CelebA faces into fake CCTV faces. Also generates your non-IID split, since each node gets its own parameter range.
Adapter MLP ← the federated part~40 lines512 → 256 → 512 residual MLP on top of frozen ArcFace embeddings. Trains in seconds on CPU. This is the only thing that ever moves between nodes.
FedAvg loop~60 linesFive node objects in one Python process. Loop: send weights out, each node trains locally, average what comes back. No Docker, no network, no framework required.
Privacy layer~70 linesClip update norm + add Gaussian noise (DP). Pairwise random masks that cancel in the sum (secure aggregation). Top-k select + mean-threshold binarise + XOR key (cancelable template).
Video pipeline + 2 dashboards~300 linesDetect → track → quality gate → embed → adapt → match → track vote → alert. Two Streamlit apps: a server console and a node review queue.

That is the whole system. Roughly 550 lines of your own code, plus library calls. Four people over twelve weeks is comfortable for that — the risk in this project is not volume, it is getting stuck on setup in week 1.

The one rule that keeps this on schedule

Persons 1 and 4 must not block each other, and Person 2 must not be blocked by anyone. Person 1 hands over embeddings in week 2; from that point every lane runs independently until they converge in week 9. If any handover slips, the person waiting starts on their report chapter rather than idling.

Week by week

Coloured letters mark whose lane each task sits in

W1

Environment and embeddings

P1Install insightface + onnxruntime, get buffalo_l running. Download LFW (via scikit-learn) and a CelebA subset — 500 identities is plenty.
P1Extract and cache 512-d embeddings for every image to a .npy file. Everything downstream reads this file, never the images.
allRepo, shared drive for figures, weekly 30-minute sync. Agree the report chapter list now.

Out: embeddings.npy + identity labels. Everyone unblocked.

W2

Degradation pipeline and the problem statement

P1Build the OpenCV degradation chain. Measure verification accuracy on clean vs degraded faces with the frozen backbone.
P4Start the video pipeline skeleton: read a video file, run face detection, draw boxes. Nothing clever yet.

Out: the accuracy-collapse chart. This single figure is your problem statement — it proves surveillance degradation breaks a state-of-the-art model.

W3

Adapter, trained centrally

P2Write the adapter MLP. Train it on all data pooled, using cosine-embedding loss on (degraded, clean) pairs of the same identity.
P1Build the non-IID split: 5 nodes, disjoint identities, each with its own degradation parameter range.
P4Add ByteTrack via supervision so each person gets a persistent track ID.

Out: centralised upper bound — the number federated learning is allowed to approach but not beat.

W4

Local-only baselines and the eval harness

P2Train each of the 5 nodes' adapters in isolation. These are your lower bounds.
P1Evaluation code: rank-1 accuracy, plus TPIR at fixed FPIR and a DET curve. Write it once, everyone reuses it.
P4Quality gate: reject faces below a minimum eye-distance, over a blur threshold, or at extreme pose.
P3Read up on DP and secret sharing. Draft the threat model chapter — it needs no code and it is a real deliverable.

Out: local-only numbers, reusable metrics module.

W5

FedAvg critical

P2The loop: broadcast global weights → each node trains a few local epochs → average the returned weights → repeat for 20–50 rounds. Five node objects in one process. No framework.
P4Watchlist matching: cosine similarity of a live embedding against the enrolled probe, with a tunable threshold.

Out: a federated model that trains without diverging.

W6

The three-way comparison critical

P2Local-only vs federated vs centralised, on the same test set. Federated must beat local-only. If it does not, the methodology has no justification — see the red-flag table below before you panic.
P4Record the demo footage: the four of you walking down a corridor past a phone camera, several passes, varied distance and lighting.

Out: the headline chart of the entire project. Everything else supports this one figure.

W7

Differential privacy

P3Clip each node's update to a fixed norm, add Gaussian noise before aggregation. Sweep the noise multiplier over four settings including zero.
P2Optional and cheap: FedProx is a single extra term in the local loss. If it takes more than a day, skip it.

Out: the privacy–utility curve. Accuracy should fall monotonically as noise rises — that shape is the result.

W8

Secure aggregation and cancelable templates

P3Pairwise masking: each pair of nodes derives a shared random mask, one adds it and the other subtracts it. Masks cancel in the sum, so the server can compute the average without seeing any single update. Print an individual masked update in your report to show it is unreadable — that screenshot is worth a paragraph of prose.
P3Cancelable template: pick the top-96 embedding dimensions, binarise by mean threshold, XOR with a per-node key. Measure the accuracy cost of the transform.

Out: masking demo, template accuracy-cost table.

W9

Integration

P4Drop the trained adapter into the video pipeline. Add track-level voting: k of n frames in a track must agree before an alert fires. Measure false alarms with and without it.
P3Optional: loss-threshold membership inference. Only if this week is calm.

Out: end-to-end run on your corridor video, with the track-voting comparison.

W10

Dashboards

P4Server console: upload a missing-person photo, generate the template, push to nodes, view incoming alerts. Node console: review queue with the matched crop, confirm or reject buttons.
allFull dry run of the demo, start to finish, and time it. Fix whatever breaks.

Out: two Streamlit apps and a working live demo.

W11

Results and figures

allEvery experiment re-run cleanly with fixed random seeds. Every chart regenerated at the same size, font and palette so the report looks deliberate.
allEach person drafts their own chapter. Do not leave writing to week 12.

Out: final figure set, chapter drafts.

W12

Report, slides, viva

allAssemble the report. Record a 3-minute demo video as insurance against a live demo failing in the room.
allRehearse two answers specifically: why did you freeze the backbone? and why is federated learning necessary here at all? Those are the questions you will get.

Out: final report, slides, recorded demo.

Red flags and what they mean

Diagnostics, so a bad number does not cost you a week

If you seeIt usually meansDo this
Degraded accuracy barely drops in W2Your degradation is too gentle — the faces are still easy.Push harder: smaller target face size, stronger blur, lower JPEG quality. You want a visible collapse, otherwise there is no problem to solve.
Adapter does not beat no-adapter in W3Wrong loss, or you are training on pairs the backbone already handles.Check you are training degraded→clean of the same identity, and that the backbone is genuinely frozen (requires_grad=False). Verify the adapter output is not collapsing to a constant.
Federated ≈ local-only in W6Nodes are too similar, so there is nothing to share.Make the split more non-IID: widen the per-node degradation ranges and shrink each node's dataset. FL only helps when a node has too little data to learn alone — that is the honest condition, so create it.
Federated beats centralisedA bug — usually test-set leakage across nodes.Check identity disjointness between train and test. Centralised is an upper bound; exceeding it means something is wrong.
Accuracy collapses at any DP noiseClipping norm is too small relative to the updates.Log the median update norm first, then set the clip near it. Do not tune noise before you have looked at that number.
insightface will not installWindows build tools, as usual.Fall back to facenet-pytorch or deepface. Any frozen embedding model works — the contribution is the adapter on top, not which backbone sits underneath. Do not lose three days here.
Constant false alarms on the demo videoThe quality gate is off or too permissive.Raise the minimum face size. Tiny and blurred crops do not produce weak matches — they produce confident wrong ones.

If week 9 arrives and you are behind

Cut in this order, and cut without guilt: membership inference, then FedProx, then the DET curve, then cancelable templates, then secure aggregation. Do not cut the three-way comparison, the DP sweep, or the video demo — those three are the project. A clean, small, working system with one honest novelty claim scores better than an ambitious one that does not run in the room.
